Plugins instalados

superpowers

v6.4.1

El plugin central que habilita todo el ecosistema de skills avanzados: metodologías de desarrollo, debugging sistemático, brainstorming, code review, ejecución de planes y más. Sin este plugin, los demás skills de proceso no funcionan.

Cuándo: Siempre activo en background. Se activa automáticamente con los /skills de superpowers.

frontend-design

oficial

Skill especializado en diseño de interfaces de usuario. Genera diseños distintivos y de producción con guías de estilo, componentes, layouts y decisiones visuales fundamentadas.

Cuándo: Antes de construir cualquier UI — ejecutá /frontend-design para obtener un contrato de diseño antes de codear.

ponytail

v4.10.0

Fuerza la solución más simple posible. Audita código en busca de sobre-ingeniería, abstracción prematura y complejidad innecesaria. Tiene 6 sub-skills: /ponytail, /ponytail-audit, /ponytail-review, /ponytail-debt, /ponytail-gain, /ponytail-help.

Cuándo: Cuando el código se está complicando, después de una implementación grande, o antes de un PR. /ponytail-audit para auditar todo el repo.

Graphify

graphifyy (Python)

v0.9.69

Convierte cualquier carpeta de código, docs, papers, imágenes o videos en un grafo de conocimiento navegable. Genera visualización HTML interactiva, JSON para GraphRAG, y un reporte en lenguaje natural. Detecta comunidades y conexiones no obvias entre archivos.

Cuándo: Para entender arquitectura de un proyecto desconocido, mapear dependencias, o consultar relaciones entre módulos.

Comandos clave

skill

Invocá con /graphify o con los comandos CLI:

graphify . — grafo del proyecto actual
graphify <ruta> — grafo de una carpeta específica
graphify https://github.com/... — clonar y graficar un repo
graphify query "¿cómo funciona X?" — consulta en lenguaje natural
graphify explain "NombreClase" — explicación de un nodo
graphify path "ModuloA" "ModuloB" — camino más corto entre dos conceptos
graphify <ruta> --update — actualización incremental

Suite GSD (Get Shit Done)

Sistema completo de gestión de proyectos integrado en Claude Code. Maneja todo el ciclo: idea → roadmap → fases → planificación → ejecución → verificación.

Nuevo proyecto

/gsd-new-project — inicializar con roadmap, research y fases desde cero.

Avanzar al siguiente paso

/gsd-next — detecta qué viene y avanza automáticamente.

Planificar una fase

/gsd-plan-phase — crea un plan detallado con tareas y dependencias.

Ejecutar una fase

/gsd-execute-phase — ejecuta todos los planes con commits atómicos.

Debug sistemático

/gsd-debug — debugging con método científico, checkpoints y sesiones.

Code review

/gsd-code-review + /gsd-code-review-fix — revisar y auto-corregir código.

Verificar trabajo

/gsd-verify-work — valida que lo construido cumple los objetivos.

Shipear

/gsd-ship — crea PR, corre review y prepara el merge.

Salud del proyecto

/gsd-health — diagnostica el directorio de planificación.

Progreso

/gsd-progress — estado actual, fases completadas y pendientes.

Notas rápidas

/gsd-note — captura ideas sin fricción. /gsd-add-todo — agrega tarea.

Backlog

/gsd-add-backlog / /gsd-review-backlog — gestionar ideas futuras.

Pausar / Retomar

/gsd-pause-work / /gsd-resume-work — handoff de contexto entre sesiones.

Seguridad

/gsd-secure-phase — verifica amenazas y mitigaciones implementadas.

UI/AI phases

/gsd-ui-phase / /gsd-ai-integration-phase — contratos de diseño especializados.

Tareas autónomas

/gsd-autonomous — ejecuta todas las fases restantes automáticamente.

Mapa del código

/gsd-map-codebase — análisis paralelo de arquitectura, tech, calidad.

Agregar tests

/gsd-add-tests — genera tests para código completado.

Rollback seguro

/gsd-undo — revierte git de forma segura.

Documentación

/gsd-docs-update — genera o actualiza docs del proyecto.

Superpowers — Skills de proceso

Metodologías que Claude aplica antes de actuar. Definen el cómo, no el qué. Se activan automáticamente según el contexto.

brainstorming

proceso

Exploración estructurada de opciones antes de implementar. Obligatorio antes de cualquier tarea de construcción.

Cuándo: "Construyamos X", cualquier feature nueva, decisiones de arquitectura.

systematic-debugging

proceso

Debugging con método científico: hipótesis, pruebas, aislamiento. Evita el debugging por intuición.

Cuándo: Ante cualquier bug o comportamiento inesperado. Siempre antes de tocar código.

executing-plans

proceso

Metodología para ejecutar planes de implementación con checkpoints, commits atómicos y manejo de desvíos.

Cuándo: Al ejecutar un plan ya diseñado.

writing-plans

proceso

Estructura para crear planes de implementación de alta calidad antes de ejecutar.

Cuándo: Cuando tenés una spec y necesitás planificar la ejecución.

requesting-code-review

proceso

Prepara y estructura un code review correcto antes de pedirlo.

Cuándo: Al completar una tarea, antes de hacer merge.

receiving-code-review

proceso

Cómo procesar y aplicar feedback de code review de forma efectiva.

Cuándo: Cuando recibís un review con cambios solicitados.

verification-before-completion

proceso

Checklist de verificación antes de declarar una tarea como completa. Previene falsos "done".

Cuándo: Siempre antes de reportar trabajo como terminado.

test-driven-development

proceso

Flujo TDD: tests primero, luego implementación. Mantiene cobertura y diseño limpio.

Cuándo: Al implementar cualquier funcionalidad nueva.

subagent-driven-development

proceso

Delegar implementación a sub-agentes especializados para tareas grandes o paralelas.

Cuándo: Tareas de implementación complejas que se pueden paralelizar.

using-git-worktrees

proceso

Usar git worktrees para trabajar en features en ramas aisladas sin afectar el árbol principal.

Cuándo: Al comenzar una feature branch nueva.

finishing-a-development-branch

proceso

Pasos para cerrar correctamente una rama de desarrollo antes del merge.

Cuándo: Cuando la implementación está lista para integrar.

dispatching-parallel-agents

proceso

Estrategia para lanzar múltiples agentes en paralelo cuando hay tareas independientes.

Cuándo: Ante 2+ tareas independientes simultáneas.

Hooks — Automatizaciones

Scripts que se ejecutan automáticamente en respuesta a eventos de Claude Code. No requieren intervención.

  • SessionStart

    Chequeo de actualizaciones GSD — verifica si hay nuevas versiones de la suite GSD al iniciar cada sesión.

  • SessionStart

    Estado de sesión GSD — carga el contexto de la sesión anterior, fases activas y estado del proyecto.

  • PreToolUse · Write/Edit

    prompt-guard — detecta posibles intentos de prompt injection en archivos antes de escribir.

  • PreToolUse · Write/Edit

    read-guard — verifica que el archivo a modificar fue leído previamente (evita escrituras a ciegas).

  • PreToolUse · Write/Edit

    workflow-guard — asegura que las ediciones respetan el flujo GSD activo (no saltear fases).

  • PreToolUse · Bash

    validate-commit — valida que los commits cumplen las convenciones antes de ejecutar git commit.

  • PostToolUse · Bash/Edit/Write/Agent

    context-monitor — monitorea el uso de contexto y avisa cuando se acerca al límite.

  • PostToolUse · Read

    read-injection-scanner — escanea el contenido leído en busca de prompt injection antes de procesarlo.

  • PostToolUse · Write/Edit

    phase-boundary — detecta si una escritura cruzó el límite de una fase GSD y actualiza el estado.
